# Requirements — Реестр прав агентов: YAML-файл и локальный CLI (check, expired)

## Что здесь задано

Документ переводит charter в проверяемые требования к поведению одного локального инструмента:
YAML-файл прав на ПК пользователя и CLI на Python с двумя командами — `check <агент> <действие>
<ресурс>` и `expired`. Каждое требование сформулировано как наблюдаемый снаружи результат: что
пользователь видит в терминале и какой код выхода получает при заданном файле прав, заданных
аргументах и заданной дате. Внутреннее устройство (модули, классы, порядок разбора) здесь не
задаётся и остаётся за стадией design.

Идентификаторы `FR-01`–`FR-05` и `NFR-01`–`NFR-07` сохранены из charter без изменений: текст уточнён
до внешне проверяемой формы, смысл, приоритет и приёмка не изменены. Требования `FR-06`–`FR-10` и
`NFR-08`–`NFR-11` добавлены, чтобы ограничения charter `CON-01`–`CON-13` получили проверяемую форму;
каждое такое требование ссылается на ограничение charter, из которого оно выведено, и ни одной новой
цели не вводит. Полное покрытие целей, ограничений и метрик charter — в разделе «Трассировка».

## Functional Requirements

#### FR-01: check отвечает «разрешено/запрещено» и почему

**Priority**: Must

`check <агент> <действие> <ресурс>` печатает один из двух ответов — «разрешено» или «запрещено» — и
причину. Причина разрешения: найдена действующая запись, в ответе показаны кто выдал и до какого
числа. Причины запрета: срок записи истёк либо записи нет. Совпадение всех трёх полей запроса с
полями записи точное, без масок и подстановок. Дата «до какого числа» включительна: в сам день
окончания запись действует. Если на одно и то же сочетание агента, действия и ресурса записей
несколько и хоть одна действует, ответ «разрешено» и показана действующая запись. При пустом списке
прав ответ «запрещено: записи нет».

- **Traces**: charter#G-01, charter#J-01, charter#J-03, charter#CON-02, charter#M-01
- **Acceptance**: для действующей записи вывод содержит «разрешено», кто выдал и до какого числа — в
  том числе при запуске в сам день окончания; при запуске на следующий день после даты окончания
  вывод содержит «запрещено» и причину «срок истёк»; при отсутствии точно совпадающей записи вывод
  содержит «запрещено» и причину «записи нет»; запись со значением `*` в поле не отвечает на запрос
  с другим значением этого поля (ответ — «запрещено: записи нет»); при двух записях с одинаковыми
  агентом, действием и ресурсом, из которых одна просрочена, вывод — «разрешено» с полями
  действующей записи; при файле с пустым списком прав вывод — «запрещено: записи нет».

#### FR-02: expired перечисляет просроченные и истекающие в 7 дней

**Priority**: Must

`expired` печатает две раздельные, явно озаглавленные группы: просроченные права и права, истекающие
в ближайшие 7 дней. Каждая строка содержит все пять полей записи: агент, ресурс, действие, кто
выдал, до какого числа. Право с датой окончания сегодня относится к истекающим. Записи с датой
окончания позже, чем сегодня плюс 7 дней, не выводятся. Если на одно право несколько записей, каждая
попадающая в группы запись выводится отдельной строкой.

- **Traces**: charter#G-02, charter#J-02, charter#CON-06, charter#CON-11, charter#M-02
- **Acceptance**: запись с датой окончания раньше сегодняшней появляется в группе просроченных;
  запись с датой от сегодня до сегодня плюс 7 дней включительно — в группе истекающих; запись с
  более поздней датой не появляется ни в одной группе; каждая выведенная строка содержит агента,
  ресурс, действие, кто выдал и до какого числа. Контрольный пример при сегодняшней дате
  23 ноября 2026: даты до 22 ноября включительно — просроченные, с 23 по 30 ноября включительно —
  истекающие, 1 декабря не выводится. Две записи на одно право, обе попадающие в группы, дают две
  строки.

#### FR-03: Проверка файла прав при чтении

**Priority**: Must

Обе команды проверяют файл прав при чтении. Если YAML сломан, у записи нет любого из обязательных
полей или дата окончания задана неверно, команда печатает сообщение с указанием места ошибки (файл
и запись) и не печатает «разрешено». Права без срока не бывает: запись без даты окончания — ошибка.
Отсутствующий файл прав — ошибка. Пустой список прав ошибкой не считается.

- **Traces**: charter#G-01, charter#J-03, charter#CON-01, charter#CON-05, charter#NFR-01
- **Acceptance**: для сломанного YAML, для записи без любого из пяти полей (агент, ресурс, действие,
  кто выдал, до какого числа) и для записи с неверной датой обе команды — `check` и `expired` —
  печатают сообщение с местом ошибки, и `check` не печатает «разрешено»; при отсутствующем файле
  прав `check` завершается с кодом 2; при файле с пустым списком прав ни одна команда не сообщает об
  ошибке (`check` отвечает «запрещено: записи нет», `expired` печатает две пустые группы и
  завершается с кодом 0).

#### FR-04: Коды выхода check и подсказка по вызову

**Priority**: Should

Код выхода `check`: 0 — разрешено, 1 — запрещено, 2 — ошибка. На неизвестную команду или неверное
число аргументов инструмент печатает сообщение об ошибке с подсказкой, как вызывать, и завершается с
кодом 2.

- **Traces**: charter#G-01, charter#J-01, charter#CON-12
- **Acceptance**: `check` завершается кодом 0 при ответе «разрешено», кодом 1 при ответе «запрещено»
  (включая причины «срок истёк» и «записи нет») и кодом 2 при любой ошибке, в том числе ошибке файла
  прав; неизвестная команда и неверное число аргументов `check` дают сообщение об ошибке, в котором
  присутствует подсказка вызова, и код 2.

#### FR-05: Короткая понятная ошибка без трассировки Python

**Priority**: Must

Когда команда не справилась, пользователь видит одну строку: что случилось и где (файл, запись).
Трассировки Python в выводе нет. Код выхода — 2 у обеих команд. Ответа «разрешено» или «запрещено»
при этом нет; неполный список `expired` не выводится.

- **Traces**: charter#G-01, charter#G-02, charter#J-01, charter#J-02, charter#NFR-05
- **Acceptance**: при отсутствующем файле, при сломанном файле и при неверной записи обе команды
  печатают одну строку с причиной и местом ошибки, в выводе нет слов `Traceback` и строк стека
  Python, код выхода — 2; в этом же выводе нет ни «разрешено», ни «запрещено», ни строк групп
  `expired`.

#### FR-06: Запуск, выбор файла прав и форма вывода

**Priority**: Must

Вход инструмента — файл прав и аргументы командной строки. Путь к файлу задаётся параметром
`--file`; без этого параметра используется `permissions.yaml` в текущем каталоге. Выход — текст в
терминал и код выхода; других каналов вывода у инструмента нет.

- **Traces**: charter#CON-12, charter#CON-01, charter#CON-07, charter#G-01, charter#M-01
- **Acceptance**: вызов с `--file <путь>` читает указанный файл (ответ соответствует его
  содержимому, а не файлу в текущем каталоге); вызов без `--file` в каталоге с `permissions.yaml`
  читает этот файл; вызов без `--file` в каталоге без `permissions.yaml` даёт ошибку по FR-05 с
  кодом 2 и упоминанием ожидаемого пути; весь результат обеих команд появляется в терминале, и после
  их работы в файловой системе нет новых файлов (проверяется вместе с NFR-04).

#### FR-07: «Сегодня» — локальная дата компьютера; код выхода expired

**Priority**: Must

Границы групп `expired` и проверка срока в `check` считаются от «сегодня» — локальной календарной
даты компьютера, на котором запущена команда. Время суток на результат не влияет. `expired`, когда
ошибок нет, завершается с кодом 0 независимо от того, нашлись просроченные и истекающие права или
нет.

- **Traces**: charter#CON-11, charter#G-02, charter#M-02, charter#FR-02
- **Acceptance**: при одной и той же локальной дате компьютера два запуска в разное время суток
  (например, сразу после полуночи и поздно вечером) дают одинаковые группы `expired` и одинаковый
  ответ `check`; при сдвиге локальной даты компьютера на один день вперёд запись с датой окончания
  «вчера» переходит из группы истекающих в группу просроченных, а `check` по ней меняет ответ с
  «разрешено» на «запрещено: срок истёк»; `expired` без ошибок завершается кодом 0 и при пустых
  группах, и при непустых.

#### FR-08: Запись права — ровно пять полей, значения читаются как написаны

**Priority**: Must

Запись о праве состоит из пяти обязательных полей: агент, ресурс, действие, кто выдал, до какого
числа. Значения полей агента, ресурса, действия и «кто выдал» сравниваются и выводятся так, как они
написаны в файле, без превращения в логические значения и числа. Дата окончания понимается
одинаково, записана она без кавычек или в кавычках.

- **Traces**: charter#CON-05, charter#RK-05, charter#NFR-01, charter#FR-03
- **Acceptance**: две записи, отличающиеся только тем, что дата окончания записана как
  `2026-11-30` и как `'2026-11-30'`, дают одинаковый ответ `check` и попадают в одну и ту же группу
  `expired`; запись, у которой значение поля записано как `no`, `yes`, `on`, `off`, `null` или
  `0007`, выводится именно в этом виде, и `check` с таким же значением аргумента находит её
  (ответ «разрешено» при действующем сроке); отсутствие или пустое значение любого из пяти полей
  даёт ошибку по FR-03 и FR-05.

#### FR-09: Только две команды; инструмент не изменяет реестр

**Priority**: Must

У инструмента есть ровно две команды — `check` и `expired`. Команд выдачи, продления, удаления
записей, импорта и синхронизации нет: реестр правится пользователем вручную. Любое другое имя
команды — ошибка по FR-04.

- **Traces**: charter#CON-06, charter#CON-01, charter#OUT-03, charter#OUT-08, charter#NFR-02
- **Acceptance**: в подсказке вызова перечислены только `check` и `expired`; вызов с любым другим
  именем команды (например, `grant`, `renew`, `revoke`, `import`, `sync`) даёт сообщение об ошибке с
  подсказкой и код 2 и не изменяет файл прав; после любой последовательности вызовов обеих команд
  побайтовое содержимое файла прав совпадает с исходным.

#### FR-10: Значения полей выводятся как есть, без маскирования и поиска секретов

**Priority**: Should

Вывод обеих команд показывает значения полей записи полностью, без маскирования и сокращения:
скрывать в реестре нечего, секретов в нём нет. Поиска и проверки секретов в файле прав инструмент не
делает — это явно вне границ.

- **Traces**: charter#CON-08, charter#OUT-07, charter#G-01, charter#M-01
- **Acceptance**: значение каждого из пяти полей появляется в выводе `check` (для показанной записи)
  и `expired` в том же виде, в каком оно записано в файле, без символов маскирования; инструмент не
  печатает предупреждений о найденных секретах и не меняет вывод в зависимости от того, похоже
  значение поля на токен или нет.

## Non-Functional Requirements

#### NFR-01: Ноль ошибочных «разрешено»

**Priority**: Must

Ошибочного «разрешено» быть не должно: при любом сомнении — записи нет, срок истёк, файл сломан или
не читается — `check` не отвечает «разрешено». Допустимая доля ошибочных «разрешено» — ноль. Лишнее
«разрешено» хуже лишнего «запрещено».

- **Category**: security
- **Traces**: charter#NFR-01, charter#CON-02, charter#G-01
- **Acceptance**: в наборе проверок, включающем отсутствие записи, истёкший срок, сломанный YAML,
  отсутствующий файл и файл без прав чтения, `check` ни в одном случае не печатает «разрешено» и ни
  в одном случае не завершается кодом 0.

#### NFR-02: Предсказуемость ответа

**Priority**: Must

Ответ предсказуем: один и тот же файл прав и одна и та же локальная дата дают один и тот же вывод.
Команды только читают файл прав и не меняют его.

- **Category**: quality
- **Traces**: charter#NFR-02, charter#M-01
- **Acceptance**: десять последовательных запусков каждой команды с тем же файлом и той же локальной
  датой дают побайтово одинаковый вывод и одинаковый код выхода — в том числе одинаковый порядок
  строк в группах `expired`; после этих запусков содержимое файла прав не изменилось.

#### NFR-03: Ответ без заметного ожидания

**Priority**: Must

Команды отвечают без заметного ожидания: обе выдают результат сразу при вызове, без фоновой
обработки и без шага подготовки данных.

- **Category**: perf
- **Target**: не хуже значения из Q-01; до ответа на Q-01 действует допущение A-01
- **Traces**: charter#NFR-03, charter#Q-01
- **Acceptance**: на файле прав объёмом до 1000 записей на ПК пользователя каждая команда печатает
  результат и завершается не дольше 2 секунд от вызова (допущение A-01); после завершения команды не
  остаётся фоновых процессов, продолжающих работу. Окончательный порог заменяется ответом на Q-01
  без изменения формы проверки.

#### NFR-04: Никакой записи и никаких журналов

**Priority**: Must

Недопустима любая запись: команды не меняют файл прав, не создают других файлов и не пишут журналов;
обращения не логируются. Результат существует только на экране.

- **Category**: security
- **Traces**: charter#NFR-04, charter#CON-07, charter#CON-10
- **Acceptance**: после запусков обеих команд — успешных и завершившихся ошибкой — содержимое и
  время изменения файла прав не изменились, а в рабочем каталоге, домашнем каталоге пользователя и
  каталоге временных файлов не появилось новых файлов и каталогов, созданных инструментом.

#### NFR-05: Никакой молчаливой потери записи

**Priority**: Must

Недопустима молчаливая потеря записи: если одну запись не удалось прочитать, команда сообщает об
ошибке, а не пропускает её.

- **Category**: quality
- **Traces**: charter#NFR-05, charter#FR-03, charter#NFR-07
- **Acceptance**: в файле из нескольких записей, где одна неверна (нет поля или неверная дата), а
  остальные верны, обе команды печатают ошибку с местом этой записи и код 2; ни `check`, ни
  `expired` не выдают результат так, будто неверной записи в файле нет.

#### NFR-06: Нулевая стоимость владения

**Priority**: Must

Платных сервисов и платных лицензий нет: работа инструмента стоит 0 рублей в месяц.

- **Category**: cost
- **Target**: 0 рублей в месяц
- **Traces**: charter#NFR-06, charter#CON-04
- **Acceptance**: для работы обеих команд не требуется ни один платный сервис, подписка или платная
  лицензия; установка и запуск выполняются без регистрации и оплаты, счёт за месяц работы
  инструмента — 0 рублей.

#### NFR-07: Полнота группы просроченных важнее лишней строки

**Priority**: Must

Для `expired` хуже пропустить просроченное право, чем показать лишнее.

- **Category**: quality
- **Traces**: charter#NFR-07, charter#G-02, charter#M-02
- **Acceptance**: для файла прав, где заранее известно множество записей с датой окончания раньше
  сегодняшней, группа просроченных в выводе `expired` содержит их все; расхождение в сторону лишней
  выведенной строки приёмку не нарушает, отсутствие хотя бы одной просроченной записи — нарушает.

#### NFR-08: Никаких сетевых обращений

**Priority**: Must

Данные хранятся и обрабатываются только на ПК пользователя. Любой выход в сеть недопустим: ни
обращений к GitHub и облакам, ни телеметрии, ни проверок обновлений.

- **Category**: security
- **Traces**: charter#CON-03, charter#OUT-01, charter#NFR-04
- **Acceptance**: при полностью отключённой сети вывод и коды выхода обеих команд совпадают с
  полученными при включённой сети; наблюдение за процессом во время работы обеих команд не фиксирует
  ни одного исходящего сетевого соединения и ни одного DNS-запроса.

#### NFR-09: Стек — Python 3.12+ и единственная зависимость PyYAML

**Priority**: Must

Инструмент — CLI на Python 3.12 или новее с единственной сторонней зависимостью PyYAML.

- **Category**: constraint-compliance
- **Traces**: charter#CON-04, charter#NFR-06, charter#CON-13
- **Acceptance**: в чистом окружении Python 3.12 с установленным только PyYAML обе команды работают
  и проходят приёмку FR-01 и FR-02; список сторонних пакетов этого окружения, кроме PyYAML, пуст;
  установка не требует компиляторов и системных пакетов помимо самого Python.

#### NFR-10: Работа без сервера, базы данных и настройки

**Priority**: Should

Инструмент остаётся посильным для одного человека: ни сервера, ни базы данных, ни шага настройки
перед первым запуском.

- **Category**: operability
- **Traces**: charter#CON-13, charter#CON-09, charter#NFR-03
- **Acceptance**: в пустом каталоге с одним файлом `permissions.yaml` обе команды работают сразу
  после установки Python и PyYAML — без запуска сервера, без создания базы данных и без файла
  конфигурации; после завершения команды в системе не остаётся фоновых процессов и служб,
  принадлежащих инструменту.

#### NFR-11: Приёмка по выводу команд, без отдельных артефактов

**Priority**: Should

Приёмку подтверждает сам пользователь по выводу обеих команд на его собственных примерах.
Отдельного документа приёмки, журналов аудита и доказательных артефактов не требуется, и инструмент
их не производит.

- **Category**: quality
- **Traces**: charter#CON-10, charter#NFR-04, charter#P-01
- **Acceptance**: приёмка выполняется запуском `check` и `expired` на примерах пользователя и
  сравнением вывода с ожидаемым — других артефактов она не требует; инструмент при этом не создаёт
  ни отчётов, ни журналов аудита (проверяется вместе с NFR-04).

## Допущения

- **A-01** До ответа на Q-01 порог «без заметного ожидания» в NFR-03 принят как 2 секунды на файле
  до 1000 записей. Основание: charter задаёт цель NFR-03 ссылкой на открытый Q-01, а требование
  должно быть проверяемым снаружи уже сейчас. Ответ на Q-01 заменяет число, не меняя формы проверки.
- **A-02** «Побайтовое совпадение вывода» в NFR-02 и FR-09 проверяется при неизменной локальной дате
  компьютера: смена даты — допустимая причина различия вывода (FR-07).

## Out of Scope

Границы charter действуют без изменений и требований не порождают: интеграции и сеть (OUT-01),
принуждение и реальный доступ (OUT-02), изменение реестра командами (OUT-03), маски, роли, группы и
наследование (OUT-04), уведомления и расписание (OUT-05), вопросы вне реестра (OUT-06), поиск
секретов (OUT-07), чтение сторонних источников сведений о правах (OUT-08). Требования, которые
делают эти границы наблюдаемыми: FR-01 (только точное совпадение, без масок), FR-09 (только две
команды, реестр не изменяется), FR-10 (секреты не ищутся), NFR-08 (ноль сетевых обращений).
