# Behaviour Spec — Реестр прав агентов: CLI `check` и `expired`

## Что здесь задано

Документ переводит требования `FR-01`–`FR-10` и `NFR-01`–`NFR-11` в сценарии, наблюдаемые снаружи:
дан файл прав и локальная дата компьютера, запущена команда — пользователь видит заданный текст в
терминале и получает заданный код выхода. Каждый сценарий описывает только то, что видно из
терминала и из файловой системы после работы команды. Внутреннее устройство (модули, порядок разбора
YAML, структуры данных) здесь не задаётся и остаётся за стадией design.

Новых целей и новых обязательств сценарии не вводят: они перечисляют наблюдаемые случаи уже
принятых требований. Там, где требование допускает несколько прочтений, прочтение зафиксировано
допущением `A-B01`–`A-B06` со ссылкой на открытый вопрос требований, который это прочтение закрывает
или оставляет за design; допущение названо явно, чтобы сценарий читался единственным образом.

## Соглашения

- **Поля записи** названы по роли: агент, ресурс, действие, кто выдал, до какого числа. Имена ключей
  YAML и раскладка файла здесь не фиксируются — это Q-06, решение стадии design. Сценарии написаны
  так, что от имён ключей не зависят: опорные примеры заданы таблицами.
- **Сегодня** — локальная календарная дата компьютера, на котором запущена команда (FR-07). Во всех
  контрольных примерах сегодня — `2026-11-23`.
- **«Вывод содержит X»** означает: в тексте, напечатанном командой в терминал, присутствует X.
  Точные формулировки сообщений здесь не предписываются — предписано, какие сведения в выводе есть.
- **Код выхода** — код завершения процесса команды.
- `check` вызывается как `check <агент> <действие> <ресурс>` (порядок аргументов — из FR-01).

**Реестр R1** — восемь записей:

| 2 | build-bot | repo/app | write | alice | 2026-11-23 |
| 3 | deploy-bot | cluster/prod | deploy | bob | 2026-11-22 |
| 4 | deploy-bot | cluster/prod | deploy | carol | 2026-12-05 |
| 5 | audit-bot | repo/app | read | bob | 2026-11-30 |

| 7 | deploy-bot | cluster/stage | deploy | dave | 2026-11-25 |
| 8 | deploy-bot | cluster/stage | deploy | erin | 2026-11-20 |

**Реестр R0** — файл с пустым списком прав (ни одной записи).

**Реестр R2** — одна запись: агент `*`, ресурс `repo/app`, действие `read`, кто выдал `alice`,
до какого числа `2026-12-31`.

**Реестр R3** — одна запись: агент `Build-Bot`, ресурс `repo/app`, действие `read`, кто выдал
`alice`, до какого числа `2026-12-31`.

**Реестр R4** — две записи: (а) агент `no`, ресурс `0007`, действие `off`, кто выдал `null`,
до какого числа `2026-12-31` без кавычек; (б) агент `build-bot`, ресурс `repo/app`, действие `read`,
кто выдал `alice`, до какого числа `'2026-12-31'` в кавычках.

## Допущения этой стадии

Каждое допущение фиксирует одно прочтение там, где требование допускало несколько, и названо, чтобы
сценарий читался единственным образом. Ни одно из них не расширяет границы требований.

- **A-B01** Сравнение значений полей при точном совпадении (FR-01) — посимвольное: регистр значим,
  краевые пробелы значимы, никакого приведения вида инструмент не делает. Основание: FR-01 задаёт
  совпадение «точное, без масок и подстановок», а NFR-01 запрещает «разрешено» при сомнении; Q-09
  требований оставляет вопрос открытым, и сценарий BEH-07 делает выбранное прочтение наблюдаемым.
- **A-B02** Верной записью даты окончания считается только `ГГГГ-ММ-ДД` (в кавычках или без);
  любая другая запись — ошибка по FR-03 и FR-05. Основание: FR-08 называет верными именно
  `2026-11-30` и `'2026-11-30'`, NFR-01 запрещает «разрешено» при сомнении. Это рабочее прочтение
  Q-08; расширение набора верных записей — решение стадии design, сужение приёмки BEH-16 не меняет.
- **A-B03** «Место ошибки» в единственной строке сообщения (FR-03, FR-05) считается указанным, если
  в строке есть путь к файлу прав и хотя бы один указатель на сбойное место: номер записи в списке
  либо номер строки файла. Основание: Q-07 требований оставляет выбор указателя за design; сценарии
  BEH-14…BEH-19 проверяют наличие указателя, а не его вид.
- **A-B04** Лишнее поле записи, не входящее в пятёрку, и повторённый ключ поля — ошибка по FR-03, а
  не молчаливое игнорирование. Основание: FR-08 задаёт «ровно пять полей», NFR-05 запрещает
  молчаливую потерю записи; Q-11 требований требует назвать решение явно, BEH-17 делает его
  наблюдаемым.
- **A-B05** «Та же локальная дата» и «сдвиг даты» в BEH-23 и BEH-24 проверяются подменой локальной
  даты в окружении запуска команды, а не параметром или третьей командой инструмента. Основание:
  приёмка FR-07 сформулирована как «сдвиг локальной даты компьютера», FR-09 оставляет ровно две
  команды, FR-06 — ровно один параметр `--file`. Это рабочее прочтение Q-10; иной способ,
  не добавляющий команд и параметров, приёмку не меняет.
- **A-B06** Опорные примеры заданы таблицами полей по роли, а не текстом YAML, потому что раскладка
  файла и имена ключей — открытый Q-06 и решение стадии design. Файлы примеров собираются из таблиц
  по раскладке, зафиксированной на design; ожидаемые выводы и коды выхода сценариев от неё не
  зависят.
