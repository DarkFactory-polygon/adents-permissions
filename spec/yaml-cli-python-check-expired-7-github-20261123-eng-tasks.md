действие, кто выдал, до какого числа). Решение продиктовано требованиями, а не вкусом: `FR-08`
задаёт ровно пять обязательных полей, `FR-03` требует указать место сбойной записи — значит записи
должны быть элементами одного списка с устойчивым порядковым номером, а `NFR-10` запрещает шаг
настройки — значит имён ключей, настраиваемых пользователем, быть не может. Единственный ключ
верхнего уровня выбран, чтобы отсутствие ключа и посторонний ключ были наблюдаемой ошибкой `FR-03`,
а не молчаливо прочитанным пустым реестром (`NFR-05`, `NFR-01`). Эта раскладка — та самая,
по которой собираются файлы опорных примеров `R0`–`R4` (`A-B06` сценариев). Решение зафиксировано
в `D-01`.

**Q-07 — resolved:**

«Место ошибки» в единственной строке сообщения — и номер записи, и номер строки файла: сообщение
несёт путь к файлу, номер строки (при известной позиции в файле) и порядковый номер записи в
списке, а для ошибок поля — имя поля. Выбор обоих указателей, а не одного, следует из `FR-03` и
`FR-05` («что случилось и где — файл, запись») и из `NFR-05`: пользователь правит файл руками, и
одного номера записи мало, когда записей сотни, а одного номера строки мало, когда нужно понять,
какая запись сломана. Оба указателя доступны из одного и того же механизма чтения (`D-02`), поэтому
их совмещение ничего не стоит и остаётся в пределах одной строки без трассировки Python (`FR-05`).
Дизъюнкция `A-B03` сценариев этим ответом сходится к одному виду: проверки `BEH-14`–`BEH-19`
остаются верны, их входы и форма не меняются. Этим же закрывается `Q-B02` сценариев. Решение
зафиксировано в `D-12`.

**Q-08 — resolved:**

Верной записью даты окончания считается только `ГГГГ-ММ-ДД` — четыре цифры года, два разряда месяца,

дата со временем и с часовым поясом вводила бы вторую трактовку «сегодня» помимо локальной

в `D-05`.

**Q-09 — resolved:**

Сравнение значений полей при точном совпадении — посимвольное равенство строк: регистр значим,
краевые и внутренние пробелы значимы, ни нормализации регистра, ни обрезки пробелов, ни приведения
юникод-форм инструмент не делает; сравниваются строки аргумента командной строки и строки поля
записи как они написаны. Основание — `FR-01` («совпадение точное, без масок и подстановок») и
`NFR-01`: любое приведение вида расширяет множество запросов, отвечающих «разрешено», то есть
создаёт ровно тот риск, который `NFR-01` запрещает. Прочтение `A-B01` сценариев подтверждено,
`BEH-07` и `BEH-06` выполняются без изменений. Решение зафиксировано в `D-07`.

**Q-10 — resolved:**

Проверяемость «той же даты» обеспечивается одной точкой врезки внутри процесса и подменой локальной
даты в окружении запуска — без третьей команды и без нового параметра. Внутри инструмента «сегодня»
читается ровно в одном месте (`clock.today()`, `D-06`), ядро принимает дату как аргумент функции,
поэтому модульные проверки задают её прямо, не трогая ни CLI, ни окружение. Сквозные прогоны
`BEH-23` и `BEH-24` подменяют локальную дату средствами машины прогона (часовой пояс окружения,
подмена системных часов для подпроцесса) — так, как сформулирована приёмка `FR-07` («сдвиг локальной
даты компьютера»). Переменной окружения и ключа командной строки для даты не вводится: `FR-06`
называет входами инструмента только файл прав и аргументы команды, а `FR-07` называет «сегодня»
локальной датой компьютера — дополнительный канал ввода даты противоречил бы обоим. Прочтение
`A-B05` подтверждено; выбор конкретного средства подмены на машинах прогона остаётся за qa
(`Q-B04` сценариев) и приёмку не меняет. Решение зафиксировано в `D-06`.

**Q-11 — resolved:**

Лишнее поле, не входящее в пятёрку, и повторённый ключ поля — ошибка `FR-03` с кодом 2, а не
молчаливое игнорирование; то же относится к посторонним ключам верхнего уровня и к элементу списка,
который не является отображением. Основание: `FR-08` задаёт ровно пять полей, `NFR-05` запрещает
молчаливую потерю записи, `NFR-01` запрещает «разрешено» при сомнении. Молчаливое игнорирование
дубликата особенно опасно: при двух значениях `until` у одной записи пользователь видит в файле
одну дату, а инструмент отвечал бы по другой. Дубликат ключа обнаружим только до построения
словаря, поэтому механизм чтения выбран так, чтобы ключи записи были видны списком (`D-02`,
`D-04`). Прочтение `A-B04` подтверждено, `BEH-17` выполняется без изменений.

**Q-12 — resolved:**

Порядок строк в каждой группе `expired` фиксируется как часть наблюдаемого результата: по дате
окончания в возрастающем порядке, при равных датах — по порядковому номеру записи в файле. Группы
печатаются в порядке «просроченные», затем «истекающие в ближайшие 7 дней». Основание — `NFR-02`
(побайтово одинаковый вывод при том же файле и той же дате) и назначение `expired` из `FR-02`:
пользователь просматривает список раз в неделю, и самая давняя просрочка должна стоять первой.
Номер записи как второй ключ выбран потому, что он единственный уже существующий устойчивый
признак (`D-01`) и не зависит от содержимого полей. Ответ превращает проверку `BEH-24` из
«порядок не меняется между запусками» в «порядок именно такой», не отменяя прежнюю: `BEH-09` и
`BEH-24` остаются верны, состав строк в группах не меняется. Этим закрывается `Q-B03` сценариев.
Решение зафиксировано в `D-09`.
